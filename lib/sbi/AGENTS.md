# lib/sbi: SBI証券 CSV 가져오기

`/sbi` 화면에 떨군 SBI CSV로 **총 누적손익 = 실현손익 + 평가손익 + 배당·분배금**을 보여 준다. 포트폴리오 CSV와 미국주식 約定履歴에서 확인한 보유종목은 대시보드의 SBI 계좌에도 합친다. CSV를 받는 경로와 각 항목의 뜻(화면 안내 문구)은 `guide.ts`에만 둔다.

## CSV 형식 (`csv.ts`, `parse.ts`)

- **인코딩:** SBI는 Shift_JIS(CP932)로 내려준다. UTF-8로 다시 저장한 파일도 받는다(`decodeCsvBytes`).
- **셀:** NFKC로 정규화한다. 그래서 `銘柄（コード）`는 `銘柄(コード)`, `ＮＴＴ`는 `NTT`가 된다. 행 끝의 쉼표는 버리고, 빈 줄은 표의 경계로 남긴다.
- **열:** 위치가 아니라 머리글 이름으로 찾는다(`findColumn`).
- **종류 판별:** 파일 이름이 아니라 내용으로 가린다(`detectKind`). 사용자가 다른 카드에 떨궈도 맞는 칸에 들어간다.
- **실현손익(`実現損益`):** 商品별 합계 표만 읽는다. 머리글이 `実現損益(税引前・円)`이면 세전이다.
  - `商品: すべて`로 받은 CSV(`ALLTYPE_*.csv`)에는 종목별·거래별 행이 없다. 그래서 화면의 "상세"에는 없다는 안내만 나온다. 상세 행이 든 CSV 형식은 아직 모른다.
- **배당·분배금(`配当・分配金`):** 商品별 합계 표와 건별 표를 읽는다. 금액은 세후 엔이다. 건별 금액은 소수 둘째 자리에서 끊겨 있어서, 합계와 약간 어긋나는 것은 허용한다.
  - 화면의 종목별 합계는 `group.ts`가 만든다. 銘柄名 끝의 코드·티커로 묶으므로 사명이 바뀌어도(Zホールディングス → LINEヤフー, 4689) 한 종목이다. 다만 口座(NISA·特定 등)가 다르면 줄을 따로 둔다.
  - 투자신탁 분배금은 数量의 단위를 아직 확인하지 못해서 1주당 금액을 보여 주지 않는다.
- **포트폴리오(`ポートフォリオ`):** `[표 제목 / 머리글 / 행…]`과 `[…合計 / 머리글 / 값]`이 반복되고, 끝에 `総合計`가 온다.
  - 預り 구분(特定·NISA 등)은 표 제목에서 읽는다.
  - 투자신탁의 기준가는 1만좌당 값이다. 단위는 CSV의 評価額과 맞춰 본 뒤 정한다(`fundUnitSize`).
  - **날짜가 들어 있지 않다.** 그래서 브라우저가 알려 준 파일 수정 시각(= SBI에서 받은 시각)을 기준가 날짜로 쓴다.
- **경고:** 합계가 행을 더한 값과 다를 때, 읽지 못한 표가 있을 때, 페이지가 잘렸을 때(`総件数` > `選択範囲`)는 `warnings`로 알린다. 조용히 빠지면 누적손익이 틀리기 때문이다.
  - 보유목록이 불완전하다는 경고가 있으면 `SbiPortfolio.holdingsComplete`가 `false`이고, 대시보드는 고친 뒤 다시 열 때까지 그날 스냅샷을 남기지 않는다. 정상적인 빈 목록은 완전한 것으로 본다.
- **미국주식 약정이력(`約定履歴`):** `外国株式 → 取引照会 → 約定履歴 → 米国株式(現物)` CSV를 읽는다. 최근 2년·파일당 1,000건 한계가 있어 여러 파일을 보관하고 합친다.
  - 같은 파일은 SHA-256으로, 기간이 겹치는 다른 파일의 체결은 날짜·ticker·매수/매도·수량·단가·계좌·결제일/금액(또는 거래 ID)과 파일 안 출현 순번으로 중복 제거한다. 파일 안에 값이 완전히 같은 실제 체결 여러 건은 보존한다.
  - 잔고는 매수−매도 수량과 이동평균 취득단가로만 추정한다(`us-trades.ts`). 실현손익은 절대 만들지 않는다. 잔고 0은 평가에서 빼고, 매도가 더 많으면 2년 이전 보유분 가능성을 경고한다.
  - CSV의 `受渡金額/決済損益`은 결제금액으로 저장하고 수량×단가와의 차이를 수수료 추정값으로 둔다. 정확한 SBI 평균단가는 보정 화면에서 USD 또는 JPY로 고친다.

## 평가 (`evaluate.ts`)

- **가상 보유종목:** CSV 보유종목은 `portfolio.json`에 쓰지 않는다. 읽을 때마다 SBI 계좌(`pickSbiAccount`: 엔화 SBI 계좌가 먼저)의 가상 보유종목으로 만든다.
  - 같은 종목이 特定·NISA에 나뉘어 있으면 대시보드용(`holdings`)은 한 줄로 합치고, 평균단가는 가중평균으로 구한다. SBI 화면은 預り 구분별 줄(`lots`)로 평가한다. 합계는 둘이 같다.
  - 미국주식도 계좌구분별 줄을 유지하고 대시보드에서는 ticker별 한 줄로 합친다. JPY 취득단가는 계좌통화 총매입액으로 저장해 환율효과를 포함한다.
- **가격:**
  - 주식: Yahoo 시세 → 저장된 시세 → CSV 현재가 순으로 쓴다(`withFallback`).
  - 투자신탁: Yahoo에 없다. 그래서 CSV 기준가를 `Quote.imported`로 넣고, 시세 조회 대상에서는 뺀다(`sbi-fund:` 심볼). 이런 종목은 `PriceStatus`가 `imported`이며 날짜가 지나도 stale로 보지 않는다.
- **신용:** 자산이 아니다. 그래서 대시보드에는 넣지 않고, SBI 화면의 평가손익에만 더한다. 평가액에 建代金을 넣지 않는 것은 SBI의 総合計와 같은 방식이다.
  - SBI의 損益에는 금리·수수료가 빠져 있다. 그래서 CSV 시점의 비용을 구해 두고, 현재가로 다시 계산할 때도 계속 뺀다.
  - 시세가 없으면 CSV의 損益을 그대로 쓴다. 같은 종목이라도 현물 표와 신용 표의 현재값이 다를 때가 있어서(2026-09 관측), 현물 표의 가격으로 다시 계산하지 않는다.
- **검증 기준:** CSV 가격만으로 평가하면 評価額·含み損益이 CSV의 `総合計`와 같아야 한다(`evaluate.test.ts`).

## 저장 (`store.ts`)

- **파일:** `data/sbi-imports.json`에 기존 3종은 종류마다 마지막 CSV의 **원문**, 미국주식은 여러 약정이력 원문과 확인한 잔고를 둔다. 파싱은 읽을 때마다 다시 하므로, 파서를 고치면 CSV를 다시 넣지 않아도 반영된다.
- **버전:** v1(기존 3종)은 그대로 읽고 다음 쓰기에서 v2(미국주식 상태 포함)로 올린다.
- **깨진 파일:** `portfolio.json`과 같은 규칙이다. 파일은 덮어쓰지 않고 `SbiImportFileError`를 던진다.

## 테스트

`fixtures.ts`의 CSV는 형식만 실제와 같은 **합성 데이터**다. 실제 계좌 CSV는 리포에 넣지 않는다(public 리포). 받은 CSV를 두는 `download/`는 git에서 제외한다.
