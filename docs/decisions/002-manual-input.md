# 002. 보유종목은 직접 입력하고, SBI만 CSV로 가져온다

- 상태: 채택 (2026-09-26, SBI CSV는 2026-09-29·미국주식은 2026-09-30 추가)
- 관련: [PR #1](https://github.com/padahkim/trizon/pull/1), [PR #3](https://github.com/padahkim/trizon/pull/3), [PR #4](https://github.com/padahkim/trizon/pull/4)

## 맥락

- 계좌는 KB증권·NH투자증권(나무)·토스증권(한국)과 SBI証券(일본) 4곳이다.
- v1을 계획할 때 사용자는 자동 연동 없이 손으로 입력하는 쪽을 골랐다. 한국 3사가 개인용 공식 API를 공개했다는 사실은 그 뒤에 알게 됐다.
- SBI証券에는 API가 없다. 대신 잔고·손익·배당을 CSV로 내려받을 수 있다.

## 결정

- 보유종목(종목·수량·평균단가·계좌통화 매입금액)은 사용자가 증권사 잔고 화면을 보고 `/holdings`에서 입력한다. 현재가와 환율만 자동으로 받는다.
- 이 데이터는 거래 원장이 아니라 **증권사 화면을 옮겨 적은 사본**이다. 그래서 대시보드는 평가손익(미실현)만 다룬다.
- SBI는 CSV(実現損益·ポートフォリオ·配当)를 `/sbi`에 넣어 가져올 수 있다. 실현손익·배당까지 합친 누적손익은 SBI 화면에서만 보여 준다.
- SBI 미국주식은 보유 CSV가 없다. 그래서 約定履歴 CSV를 합쳐 잔고를 추정하고, 사용자가 확인·보정한다. 실현손익은 만들지 않는다(実現損益 CSV와 겹치지 않게).
- CSV를 어떻게 읽고 평가하는지는 `lib/sbi/AGENTS.md`에 있다.

## 버린 대안

- **거래 원장(매수·매도 기록) 입력:** 실현손익까지 계산할 수 있지만 입력이 많고, 증권사 화면의 숫자와 맞추기 어렵다.
- **마이데이터:** 인가받은 사업자만 쓸 수 있다.

## 감수하는 것

- 사고팔 때마다 사용자가 직접 고쳐야 한다. SBI도 CSV를 다시 넣어야 한다.
- 실현손익과 배당은 SBI 계좌만 보인다.

## 다시 볼 조건 (v2 1순위 후보)

한국 3사의 공식 API로 보유종목을 자동으로 채운다. 증권사마다 spike를 한 번씩 해서 확인한 뒤, 같은 `Holding`을 채우는 동기화 어댑터를 붙인다. API 키는 `.env.local`에만 둔다.

2026-09 조사 시점의 상황은 아래와 같다. 착수 전에 다시 확인한다.

| 증권사 | 공식 API | 보유종목 조회 | 메모 |
|---|---|---|---|
| KB증권 | REST 오픈 베타(2026-07-20~) | 국내 O, 해외 미확인 | 정식 오픈은 2026 하반기 |
| NH(나무) | "Namuh PLUG" REST(2026-08-10~) | 국내·해외 O | 구 QV Open API(Windows COM)는 쓰지 않는다 |
| 토스증권 | REST OAuth2(2026-08-13 정식) | 국내·미국 O | 종목별 원화 매입금액·매입환율 필드가 없다 |
| SBI証券 | 없음 | — | CSV 가져오기 유지 |
