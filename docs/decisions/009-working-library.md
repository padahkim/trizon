# 009. 다음에 또 쓸 자산은 리포에 자리를 잡아 두고, 같은 작업을 두 번째로 할 때 만든다

- 상태: 채택 (2026-10-11)
- 관련: 006(도구 중립 지침), 007(훅으로 강제), 자리·후보·회고 형식은 `docs/working-library.md`

## 맥락

- 이 리포의 "팀"은 사람 한 명과 에이전트 셋이다. Claude Code(회사 PC), Codex(집 PC), 가끔 Antigravity를 쓴다(006). 그래서 작업 방식이 사람 사이가 아니라 PC와 도구 사이에서 갈라진다.
- 한 PC에만 있던 것을 리포로 옮긴 일이 이미 두 번 있다.
  - 설계 결정은 회사 PC Claude의 메모리와 리포 밖 계획서에만 있었다(006).
  - 머지 전에 리뷰를 확인하는 규칙도 그 메모리에만 있었다. 집 PC의 Codex는 몰랐다.
  - "같은 작업을 두 번째로 손으로 하면 스킬로 만든다"는 규칙과 개인 스킬도 지금 회사 PC의 `~/.claude`에만 있다.
- 리포에 쌓인 자산도 있다. 지침(루트·폴더별 `AGENTS.md`), 결정 기록, 훅·CLI(`scripts/`), 그리고 진행 중인 Golden Rules(`docs/golden-rules.md`)다. 그런데 006은 지침과 문서를 둘 곳만 정했다. 반복 작업의 절차를 어디에 두는지, 언제 자산으로 만드는지는 정하지 않았다.
- 반복했는데 자산이 되지 않은 작업이 있다. 결정 기록은 2026-10-10~11 이틀 동안 네 번에 걸쳐 아홉 개를 썼다(001~006을 한 번에, 007, 진행 중인 008 두 개).
  - 쓸 때마다 번호를 고르고, 형식을 기존 기록에 맞추고, `AGENTS.md` 목록에 한 줄을 더했다.
  - 2026-10-11에는 병렬 worktree 두 곳(`feat/review-gate`, `refactor/pattern-detox`)이 같은 008을 골랐다. 각자 자기 브랜치만 보고 "이어서" 붙였기 때문이다.
- 도구마다 리포의 스킬을 읽는 위치가 다르다(2026-10-11 공식 문서 기준).

| 도구 | 리포 스킬 위치 | 심볼릭 링크 |
|---|---|---|
| Codex | `.agents/skills/` (실행한 폴더부터 Git 루트까지) | 따라간다고 문서에 있다 |
| Antigravity | `.agents/skills/` | 문서에 없다 |
| Claude Code | `.claude/skills/` (`.agents/skills/`는 읽지 않는다) | 문서에 없다. 2.1.296에서 따라가는 것을 확인했다 |

## 결정

- **자리:** 다음에 또 쓸 자산은 리포에 둔다. 강의의 네 자산은 이 리포에서 이렇게 둔다.
  - 공유 Skills(반복 작업의 절차): `.agents/skills/<이름>/SKILL.md`. `.claude/skills`는 `.agents/skills`를 가리키는 심볼릭 링크 하나다.
  - 공유 MCP: 지금은 없다. 만들면 로직은 `scripts/`에 두고, 도구별 설정은 그 명령을 가리키기만 한다(007과 같은 구조).
  - 공유 지침 템플릿: 지침은 루트·폴더별 `AGENTS.md`다(006). 형식이 정해진 문서의 틀은 그 문서를 만드는 스킬 안에 둔다.
  - Golden Rules: `docs/golden-rules.md`.
- **만드는 때:** 같은 작업을 두 번째로 손으로 할 때 자산으로 만든다. 처음에는 만들지 않는다. 첫 실행의 기록이 명세가 된다.
  - 다음에 또 할 것이 보이지만 아직 한 번뿐이면, `docs/working-library.md`의 후보에 근거와 트리거만 적어 둔다.
- **모양:** 빠뜨리면 사고가 나는 확인은 훅·테스트(007), 따라 하는 절차는 스킬, 알아야 할 지식은 `docs/`로 만든다.
  - 스킬에는 절차만 쓴다. 규칙은 원본 문서(`AGENTS.md`, `docs/`)를 가리키고 옮겨 적지 않는다. 실행할 로직은 `scripts/`에 둔다.
- **주기:** PR 본문에 "Working Library" 절을 쓴다. 이번에 만든 자산, 다시 쓴 자산, 새 후보를 적는다. `.github/pull_request_template.md`가 자리를 잡아 둔다.
- **첫 자산:** 결정 기록 쓰기를 `new-decision` 스킬로 만든다.
  - 기록의 틀은 스킬 안의 `template.md` 한 곳에 둔다.
  - `npm run decision:next`는 작업 트리와 아직 머지하지 않은 로컬·원격 브랜치의 기록을 보고 다음 번호와 겹친 번호를 알려 준다.
  - `npm run check`가 번호 중복, `AGENTS.md` 목록 누락, 없는 기록을 가리키는 경로를 잡는다. 병렬 브랜치가 같은 번호를 골라도, 나중에 rebase하거나 머지하는 쪽에서 Stop 훅(007)이 돌려보낸다.
  - 번호가 겹치면 나중에 머지하는 쪽이 바꾼다.

## 버린 대안

- **강의대로 `.claude/commands/`:** Claude Code만 읽는다(006). Claude Code에서도 commands는 스킬의 옛 형식이다.
- **스킬을 도구마다 복사:** 한쪽만 고쳐져 어긋난다.
- **`.claude/skills/`를 원본으로 두고 `.agents/skills`를 링크로:** 두 도구가 같이 읽는 위치를 원본으로 두는 편이 006의 취지에 맞다. Claude Code가 `.agents/skills`를 읽게 되면 링크만 지우면 된다.
- **후보 자산을 미리 다 만들기:** 한 번도 하지 않은 작업은 무엇이 반복될지 모른다. 쓰이지 않는 자산은 코드와 어긋난 채 남는다.
- **모든 자산을 다시 나열하는 카탈로그 문서:** 명령·폴더별 지침·결정 기록은 이미 루트 `AGENTS.md`에 목록이 있다. 스킬은 각 `SKILL.md`의 `description`이 설명이다. 목록을 두 벌 두면 어긋난다.
- **틀만 모으는 `docs/templates/`:** 틀과 그 틀을 쓰는 절차가 떨어진다. 틀을 바꿀 때 스킬도 같이 고쳐야 한다.
- **여러 리포가 같이 쓰는 메타 리포:** 지금 이 자산을 쓰는 리포는 하나다.
- **결정 기록 이름을 번호 대신 날짜로:** 기존 기록 이름과 링크를 모두 바꿔야 한다. 겹친 번호는 검사로 잡는다.

## 감수하는 것

- 심볼릭 링크라서, Windows에서 `core.symlinks`가 꺼져 있으면 Claude Code가 스킬을 찾지 못한다. 지금 쓰는 PC는 둘 다 macOS다.
- Claude Code가 링크를 따라가는 것은 문서가 아니라 직접 확인한 동작이다.
- `decision:next`는 커밋된 기록과 마지막 fetch 기준의 원격 브랜치만 본다. 다른 worktree에서 아직 커밋하지 않은 기록은 보지 못한다.
- PR 회고는 에이전트가 지시를 지킨다는 전제에 기댄다. 강제하지 않는다.
- "두 번째 반복"인지는 여전히 판단이 필요하다. 세션 기록과 git 히스토리에서 근거를 찾아 정한다.

## 다시 볼 조건

- Claude Code가 `.agents/skills`를 읽게 됐을 때. 링크를 지운다.
- 후보가 쌓이기만 하고 만들어지지 않을 때, 또는 만든 스킬이 다시 쓰이지 않을 때. PR 회고의 "다시 쓴 것"을 모아 기준을 다시 본다.
- 다른 개인 리포에서 같은 자산을 두 번째로 쓰게 될 때. 메타 리포나 사용자 범위 스킬(`~/.agents/skills`)을 검토한다.
- PR 회고가 빠지는 일이 반복될 때. 훅으로 확인하는 것을 검토한다.
