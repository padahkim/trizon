# 001. 로컬 전용으로 만든다

- 상태: 채택 (2026-09-26)
- 관련: [PR #1](https://github.com/padahkim/trizon/pull/1)

## 맥락

- 한국·일본 계좌의 주식 자산을 한곳에서 보는 개인용 앱이다. 쓰는 사람은 한 명이다.
- "가볍게 먼저" 만들고 싶었다. 계정 연동, 인증, 보안 설계를 v1에서 빼고 싶었다.
- 자산 데이터는 민감하고, 리포는 public이다.

## 결정

- 내 PC에서 `npm run dev`로 띄워 쓴다. 웹 배포, DB, 로그인이 없다.
- 데이터는 `data/`의 JSON·JSONL 파일에 두고 git에서 뺀다. 서버 컴포넌트와 Server Actions가 파일을 직접 읽고 쓴다.
- 저장 계층은 `PortfolioStore` 인터페이스(`lib/store/types.ts`) 뒤에 둔다. 나중에 DB로 바꿀 때 구현만 교체한다.

## 버린 대안

- **웹 배포 + DB + 로그인:** 기기 사이 동기화가 되지만, 인증·호스팅·자산 데이터 보호를 처음부터 설계해야 한다. v1에서 얻는 것에 비해 무겁다.

## 감수하는 것

- 기기 사이 동기화가 없다. PC마다 `data/`가 따로 있고, 백업은 사용자가 폴더를 복사한다.
- DB가 해 주던 일을 직접 한다. 원자적 쓰기, 쓰기 직렬화, 깨진 파일을 덮어쓰지 않는 규칙이 여기서 나왔다(`docs/architecture.md`의 "데이터 파일").
- 실제 자산 데이터와 증권사 CSV가 리포에 들어가지 않게 지켜야 한다. 테스트 데이터는 합성으로 만든다.

## 다시 볼 조건

- 여러 기기에서 같은 데이터를 봐야 할 때. `PortfolioStore` 구현을 바꾸는 것부터 검토한다.
