# 공통 시세·시장 식별·전일종가 계약

이슈 [#55](https://github.com/padahkim/trizon/issues/55), 확인일 2026-10-30(Asia/Tokyo). **3단계 후속 구현이 따를 계약**이다. 이번 spike는 앱의 타입·API·화면을 바꾸지 않는다. 공식 근거는 [출처 조사](55-common-quotes-evidence.md), 실행 결과는 [공개 시세 관찰](55-quote-observations.md), 입력과 기대 결과는 [합성 fixture](55-common-quotes.fixtures.json)에 분리해 둔다. 합성 응답은 실제 공급자 검증 결과가 아니다.

## 현재 구현과 지원 판정

| 경로 | 현재 코드에서 확인한 것 | 판정 |
|---|---|---|

| SBI 미국 | `holdingsFromTrades` → `US:ticker` → Yahoo 티커의 `.`를 `-`로 변환; USD | 기존 지원. AAPL·BRK.B 공개 조회 성공. 티커 변경·분할에 따른 보유 자동 보정은 없음 |
| 한국 | `Market`에는 `KR`가 있으나 `quoteKeySchema`는 JP/US만 허용하고 `toYahooSymbol`은 KR에서 예외 | 앱은 아직 미지원. 공개 KOSPI/KOSDAQ 표본 조회만 성공 |
| KB·NH·토스 시세 | #50·#51·#52에 전달된 실제 API 관찰 없음 | 미확인. 계좌별 평가액을 공통 시세로 사용하지 않음 |

코드 원본: [시세 타입](../../lib/quotes/types.ts), [Yahoo adapter](../../lib/quotes/yahoo.ts), [HTTP 경계](../../lib/quotes/handler.ts), [평가](../../lib/portfolio/evaluate.ts), [시각 표시](../../lib/format.ts), [SBI CSV](../../lib/sbi/portfolio.ts). 기존 테스트 12개(`yahoo.test.ts`, `evaluate.test.ts`)로 현재 JP/US 매핑과 가격 대체·전일종가 누락 동작을 확인했다.

## 식별

- `market`의 JP/US/KR는 거래 대상의 국가 범위다. 증권사 소재국, 계좌통화, 상장시장, 체결 거래소와 구별한다. 한국 상장시장 분류는 `KOSPI | KOSDAQ | KONEX | unknown`, 시세 거래소 범위는 `KRX | NXT | composite | unknown`으로 별도 기록한다. `NXT`를 `KOSDAQ` 같은 상장시장으로 저장하지 않는다.
- 공통 시세 식별자는 기존의 `market:code`다. 같은 `KR:000001`을 KB·NH·토스 여러 계좌가 보유해도 동일한 공급자·가격 범위의 시세 한 개를 쓴다. KRX/NXT/통합 시세를 나중에 함께 제공하면 공급자 캐시에 그 범위를 분리하고, 한 평가 요청에서는 같은 종목에 같은 범위를 선택한다. 먼저 도착한 계좌의 평가액이나 최종 체결 거래소로 공통 시세를 결정하지 않는다.
- 보유 식별자는 `broker + account + market + code`이고, 종목명은 식별자가 아니다. 계좌번호·계좌 선택 토큰·종목 단축코드·표준코드는 모두 문자열이다. `"000001"`과 `"1"`, `"00100002"`와 `"100002"`를 합치지 않는다. 숫자 변환 후 `padStart`로 복원하거나, 임의 길이로 자르지 않는다. 접두사 제거도 해당 공급자의 마스터 계약에서 확인한 경우에만 한다.
- Yahoo 심볼은 adapter의 외부 식별자다. KOSPI 확인 → `code.KS`, KOSDAQ 확인 → `code.KQ`; `KR`·종목명·KRX/NXT 거래소만으로 접미사를 추측하지 않는다. 마스터/보유 응답 간 분류 충돌, 분류 미상, KONEX는 시세 매핑 보류 사유다. 숫자 코드가 같아 보여도 표준코드·상품 종류를 먼저 대조한다. ETF·우선주 등의 범위는 마스터와 표본 조회로 별도 확정한다.

## 공급자 값과 정규화

후속 adapter가 지켜야 할 의미 계약이며 현재 `Quote` 타입이 모든 메타데이터를 갖는다는 뜻은 아니다.

| 값 | 계약 |
|---|---|
| `price` | 선택한 가격 세션의 종목 단위 가격. Yahoo는 `regularMarketPrice`만 사용. 숫자로 유효해야 하며 누락/null/NaN/무한대/음수는 시세 없음. 누락을 0으로 만들지 않음 |
| `currency` | 거래 가격 통화(JP=JPY, US=USD, KR=KRW). 원화 환산 평가액의 통화와 구별. 없거나 기대 통화와 다르면 그 시세는 사용 불가 |
| `marketTime` | 선택한 **가격 필드에 대응하는 공급자 시각**을 UTC ISO로 저장. Yahoo의 초 단위 epoch는 라이브러리가 `Date`로 변환. 없거나 불명확하면 가격도 사용 보류. `receivedAt`, CSV 업로드 시각, HTTP 응답 시각, 일봉 버킷 시각을 넣지 않음 |
| 날짜·TZ | UTC 시각과 IANA TZ(JP `Asia/Tokyo`, US `America/New_York`, KR `Asia/Seoul`)로 가격의 현지 날짜를 유지. 미국은 DST를 반영하고 UTC−5를 고정하지 않음. 날짜와 TZ를 표시할 수 있어야 함 |
| 가격 세션·거래소 범위 | Yahoo `regularMarket*`는 정규장 가격 세션으로 기록. 응답의 현재 `marketState=PREPRE/POST`를 그 과거 가격의 세션으로 복사하지 않음. `preMarketPrice`·`postMarketPrice`를 현재가에 섞지 않음. `exchange` 메타데이터만으로 NXT 포함·통합 체결 가격을 입증하지 않음 |
| `previousClose` | 같은 종목·통화·가격 범위에서 공급자가 정의한 직전 정규 거래일 종가. Yahoo는 `regularMarketPreviousClose`. 전날의 달력 날짜가 아님. 분할 전후 단위가 맞아야 함. 기준일·조정 방식은 확인된 만큼 기록하고 나머지는 unknown |
| 전일종가 누락 | 외부 null/미제공/비정상 값은 정규화 시 unknown. 현재 v1 wire에서는 optional 필드 생략으로 표현하며 JSON null은 스키마에서 거절됨. 3단계 내부 모델에서 null 또는 명시적 상태 하나로 통일. `0`, 현재가, 취득가로 메우지 않음. 0 종가는 주식의 비교 기준으로 사용하지 않음 |
| 출처 | provider·외부 심볼·세션·가격 범위·확인된 지연/통화·수신시각을 추적. 수신시각은 관찰/진단 용도이며 가격의 신선도를 갱신하지 않음 |

조회에서 종목만 빠지면 개별 시세 없음, 네트워크·서버 실패/10초 제한은 전체 요청 실패다. 이번 공개 조회 성공은 SLA·모든 종목의 필드 보장·재배포 허가를 뜻하지 않는다. Yahoo 약관/공식 도움말의 이용 제한을 유지한다. 새 유료 공급자·국내 서버·IP 우회·브로커 인증 경로를 추가하지 않는다.

## 오늘변동과 대체 평가

PRD U8~U10, U44, 열린 질문 「오늘 매매한 종목의 전일 대비」를 따른다. 거래 수량 변화·실현손익·FX 하루 변동을 오늘변동에 섞지 않는다. 주가 효과는 **지금 보유수량 × (선택한 현재가 − 같은 기준의 전일종가)**다. 3단계 계좌/표시 통화 환산은 #57·#58의 FX 계약에서 이 값을 현재 환율로 환산한다.

| 상태 | 평가 가격·손익 | 오늘변동의 계산 기여 | 표시 계약 |
|---|---|---|---|
| 유효한 시세와 비교 가능한 전일종가 | 공통 시세 | 공식 계산식 | 측정됨. 실제 변동이 0인 경우와 구별 |
| 유효한 시세, 전일종가 unknown | 공통 시세로 평가액·평가손익 계산 | 0 | **전일종가 미상 · 오늘변동 미측정** |
| 시세 실패, 유효한 SBI 일본 CSV `現在値` | 그 보유 행의 CSV 가격. 평가손익은 (CSV 가격−취득단가)×보유수량 | 0 | **CSV 現在値 · 오늘변동 미측정**. CSV를 공통 시세에 승격하지 않음 |
| 그 밖의 시세 실패 | 취득단가로 평가. 평가손익 0 | 0 | **시세 없음 · 원가 평가 · 오늘변동 미측정** |

전체 요청 실패에도 행별로 같은 우선순위를 적용하고, 맨 위 요청 실패 안내/새로고침을 함께 보인다. 합계에서 보유를 빼지 않는다. 미측정 행은 계산 기여 0과 별개로 개수/포함 범위를 전달해 합계에도 일부 미측정을 표시한다. 0원/0%를 완전히 측정한 결과처럼 보이지 않는다. 원가 자체가 미상인 3단계 보유는 0원 원가로 발명하지 않으며 #57~#59의 원가 상태와 결합한다.

CSV 대체의 유효 범위는 **SBI·JP·해당 보유 행**, 유한한 0 이상 가격, 파싱 가능한 업로드 시각이다. `csvQuote.asOf`는 현재 parser에서 `now`를 넣는 업로드 시각이며 실제 시세시각이 아니다. CSV 가격의 시장시각·신선도는 미상으로 표시한다. CSV 나이가 오래됐다고 실시간 가격처럼 표시하지 않으며 이번 spike에서 임의 만료일은 추가하지 않는다. 같은 일본 종목의 계좌별 CSV 가격이 달라도 다른 행이나 공통 시세를 덮지 않는다.

기존 공통 시세의 7일 초과 무효 규칙은 유지한다(정확히 7일은 허용). 장기 휴장도 수신시각으로 기한을 연장하지 않는다. 공급자 시세시각이 미래거나 타임존 변환이 불명확한 응답은 정상 최신 시세로 승인하지 않는다.

## 휴일·시간외·분할·일봉

- 휴일·주말에는 최근 가격/시각을 유지한다. 일본의 10월 12일 휴일 뒤 10월 13일 가격에는 10월 9일 종가가 비교 대상이다. 휴일을 0원 일봉으로 만들거나 `오늘−24시간`으로 찾지 않는다. 휴일 중에도 PRD의 의미는 공급자가 제공한 마지막 거래 세션의 전일 대비이며 달력상 오늘의 실현손익이 아니다.
- 미국 장전·장후와 한국 NXT의 확장 시간에도 현 계약은 Yahoo 정규장 가격/전일종가 쌍이다. 더 늦은 시간외 가격만 붙이면 비교 의미가 바뀐다. 시간외·NXT/통합 시세를 채택하려면 가격·시각·세션·비교 종가·휴일/단축장·이용 조건을 한 공급자 계약으로 함께 검증한다. 거래시간은 변경될 수 있으므로 접미사나 고정 시각으로 세션을 추정하지 않는다.
- 예: 4:1 분할, 직전 원단위 종가 400, 현재 단위의 현재가 102, 현재 수량 4주라면 비교 종가 100 → 오늘변동 +8이다. 400을 그대로 쓰면 −1,192로 틀린다. 분할 적용 여부를 입증할 수 없으면 비교 종가 unknown으로 둔다. 조정 근거 없이 Yahoo가 이미 조정한 `close`를 다시 4로 나누지 않는다.
- Yahoo 공식 설명상 일별 `Close`는 분할 조정, `Adjusted Close`는 분할과 배당/분배 조정을 포함한다. PRD는 주가 효과이므로 배당 조정 `adjclose`를 오늘변동 기준으로 쓰지 않는다. 과거 분할이 추가 반영된 일봉은 가격 관측일과 조정 기준일의 주식 단위가 같은지도 확인해야 한다.
- **자동 일봉 fallback은 채택하지 않는다.** 필요한 경우 현재 가격의 현지 거래일보다 앞선 마지막 완료 정규장의 `close`를 선택하고, 휴장·null 봉·현재 진행 중 봉 제외, 종목/통화/TZ·거래소 범위·분할 기준 일치까지 검증해야 한다. 정렬한 배열의 뒤에서 두 번째 봉이나 `meta.previousClose`를 무조건 쓰지 않는다. 일봉의 `date`는 버킷/장 시작일 표식일 수 있어 실제 현재가 시각으로 사용할 수 없다.
- 시세의 분할 조정과 SBI 원장의 보유수량/취득단가 보정은 별도다. 이번 spike로 기존 PRD U47의 보유 자동 보정 유예를 바꾸지 않는다.

## 후속 구현과 추가 시장의 검증

1. #50/#51/#52에서 실제 통과한 증권사 한 곳의 관찰만 우선 사용한다. 세 곳 전체 완료를 공통 계약의 선행 조건으로 만들지 않는다. 이번 시점에는 세 이슈 모두 관찰 댓글이 없어 optional broker 시세 경로는 미확인이다.
2. 마스터에서 단축코드·표준코드·상품종류·KOSPI/KOSDAQ/KONEX 구분, 계좌 필드의 문자열 보존, 갱신/상장폐지/이전상장·우선주를 확인한다. KRX/NXT 구분 필드와 상장시장 구분 필드를 각각 확인한다. 공식 예제에서 다른 증권사의 필드명을 차용해 특정 증권사 지원으로 간주하지 않는다.
3. 공개 표본/합성 응답과 실제 API 관찰을 구분해 현재가·전일종가·통화·스케일·부호·날짜와 시각 결합·TZ·지연·가격 세션·거래소/통합 범위·null/0/휴장/분할을 확인한다. 시간만 있으면 수신일을 붙이지 않고 응답의 기준 거래일을 검증한다.
4. 브로커 평가액/평가손익/환산금액은 계좌 데이터다. 공통 시세를 `평가액 ÷ 수량`으로 만들지 않는다. 비교 가능한 종목 단위 시세 API가 실제 검증된 경우에만 선택 provider 후보로 둔다.
5. #59 및 시장별 후속 #62~#64에서 한국 매핑, 메타데이터, JP CSV 범위 제한, 미측정 상태·합계 표시를 구현하고 기존 JP/US 경계와 함께 테스트한다. #65는 이 상태들을 연결해서 검증한다. 지금 `evaluate`는 CSV를 JP/SBI로 제한하지 않고, 미래 시각을 거르지 않으며, 미측정 상태를 반환하지 않고, `formatMarketTime`은 날짜/TZ 없이 HH:mm만 보인다. **이 차이들은 이미 구현된 것으로 보고하지 않는다.**
6. 공급자의 본인 이용·서버 실행·캐시 보관·호출 한도·표시/재배포 조건을 확인한다. 무료·무키 조회 성공과 공개 제공 권한은 별개다. 조건·비용·실행환경 변경이 필요하면 해당 결정을 다시 연다.

## fixture와 검증 범위

JSON은 외부 호출 없이 후속 adapter/평가 경계에서 사용할 선언적 입력·기대 결과다. 현재 v1 스키마에 3단계 메타데이터가 있다고 가정하지 않는다. 기대 금액은 위 계산 예의 고정 숫자이며 구현으로 산출한 snapshot이 아니다. 코드/계좌는 합성이며 실제 마스터에 존재하거나 실제 계좌라는 뜻이 아니다. 기존 `fake` provider나 실조회에 등록하지 않는다.

- `identityCases`: 0 보존, 같은 종목의 상장시장과 거래소 구별, 분류 불명/충돌 시 매핑 보류.
- `quoteCases`: 날짜/TZ/DST, PREPRE와 가격 세션 분리, null/누락·통화 오류·수신시각 대체 금지.
- `valuationCases`: 공유 시세의 여러 계좌 적용, CSV/원가 우선순위, 미측정과 측정된 0 구별, 7일 경계.
- `dailyCases`: 휴일, 현재 진행 중 봉, 분할 단위, 배당 조정 종가 거절.

이번 검증은 공개 자료·공개 Yahoo 조회·합성 fixture·기존 회귀 테스트다. 실계좌 API·분할 당일의 실제 `regularMarketPreviousClose`·NXT/통합 시세·모든 종목/시장·공개 이용 허용은 검증 완료로 간주하지 않는다.
