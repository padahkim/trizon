# 아키텍처

1단계 기준이다. 코드가 아직 없어서 디렉토리 구조는 예정이며, 구현하면서 실제 구조로 고친다. 무엇을 만들고 무엇으로 완료를 판단하는지는 [`PRD.md`](PRD.md)에 있다.

## 스택
- Next.js 16 (App Router) + TypeScript, npm. ESLint는 `create-next-app` 기본값. Tailwind와 `src/`는 쓰지 않는다.
- 시세: `yahoo-finance2`. 서버(Server Action)에서만 부른다.
- 테스트: Vitest(단위), Playwright(e2e)
- 1단계는 로컬 실행 전용이다. 서버는 시세만 중계하고 아무것도 저장하지 않는다.

## 디렉토리 구조 (예정)
```
app/
  page.tsx                 랜딩: "trizon" + 대시보드 링크
  dashboard/page.tsx       대시보드
  dashboard/Dashboard.tsx  업로드 + 시장별 표 (client component)
  dashboard/actions.ts     Server Action: fetchQuotes
lib/                       Next 없이 도는 순수 모듈
  sbi/csv.ts               바이트 → 텍스트 → 행·셀, 열 이름으로 찾기 (v1에서 이식)
  sbi/detect.ts            내용으로 CSV 종류 판별
  sbi/portfolio.ts         ポートフォリオ → 일본 現物 보유
  sbi/us-trades.ts         約定履歴 → 미국 보유 계산
  quotes/provider.ts       QuoteProvider 인터페이스
  quotes/yahoo.ts          일본은 "<코드>.T", 미국은 티커 그대로
  quotes/fake.ts           고정 현재가 (TRIZON_QUOTES=fake)
  holdings/evaluate.ts     평가액·평가손익·시장별 합계
  holdings/store.ts        localStorage 저장·읽기 (Supabase로 바꿀 곳)
```

## 데이터 흐름
CSV는 브라우저에서 읽고 파싱한다. 서버로 가는 것은 시세를 받을 종목 코드뿐이다.

```
CSV 파일들 (한 번에 여러 개)
  → decode · parseCsv → detect
     ├ ポートフォリオ → 일본 現物 보유 (계좌구분별)
     ├ 約定履歴      → 미국 보유 계산 (계좌구분별)
     └ 판별 실패     → 오류 표시, 저장된 내용은 그대로
  → store: 종류별로 덮어써서 localStorage에 저장
  → fetchQuotes(종목 코드들) → QuoteProvider → 현재가
  → evaluate → 종목별 평가액·평가손익, 시장별 합계 → 화면
```

## CSV 읽기
- 인코딩: UTF-8(BOM 포함)로 먼저 읽고, 실패하면 Shift_JIS(CP932)로 읽는다.
- 분리: 따옴표 안의 쉼표·줄바꿈은 셀 내용으로 두고, `""`는 따옴표 하나로 읽는다. CRLF도 처리한다.
- 셀: NFKC 정규화와 앞뒤 공백 제거. 행 끝의 빈 셀은 버리고, 빈 줄은 표 경계로 남긴다.
- 열: 위치가 아니라 이름으로 찾는다. 정확히 같은 이름을 우선하고, 없으면 괄호 설명이 붙은 이름을 찾는다.
- 값: 쉼표·공백·`円`을 지우고 숫자로 바꾼다. 빈칸과 `-`는 `null`. `100.0000USD`처럼 통화가 붙은 값은 금액과 통화로 나눈다.
- 인코딩 판별, CSV 분리, NFKC 정리, 열 찾기 함수는 v1 `lib/sbi/csv.ts`(`git show v1-final:lib/sbi/csv.ts`)에서 가져와 다듬는다. v1의 다른 코드(UI, 구조, 다른 파서)는 참고하지 않는다.

### ポートフォリオ
- 셀이 하나인 행은 표 제목이다. 제목에서 계좌구분(特定·一般·NISA 등)을 읽는다.
- 現物 표: 첫 열이 `銘柄(コード)`이고 `取得単価` 열이 있는 머리글. `銘柄(コード)`, `数量`, `取得単価`, `現在値`, `評価額`을 읽는다.
- `7203 トヨタ`는 코드 `7203`과 이름으로 나눈다. `285A` 같은 영문 포함 코드도 받는다.
- 信用 표(`建単価` 열)와 投資信託 표(첫 열 `ファンド名`)는 건너뛰고 "읽지 않은 표"로 알린다.
- `…合計`, `総合計` 블록은 보유 종목으로 읽지 않는다.
- `総件数`보다 적은 행만 담긴 CSV는 일부 페이지만 받은 것으로 보고 경고한다.

### 約定履歴
- 머리글: 첫 열이 `国内約定日`이고 `銘柄コード` 열이 있는 행
- 필수 열: `国内約定日`, `銘柄`, `銘柄コード`, `商品区分`, `取引`, `預り区分`, `約定数量`, `約定単価`, `受渡金額/決済損益`. 하나라도 없으면 파싱 오류로 본다.
- `商品区分`이 `米国株式`이고 `取引`이 `現買`·`現売`인 행만 쓴다. 나머지 행은 건너뛰고 경고한다.
- 1,000행 이상이면 다운로드 한도에 닿았다고 경고한다.

### 미국 보유 계산
계좌구분과 티커마다 체결을 날짜순(같은 날은 파일 순서)으로 적용한다.

```
現買: 수량 += n, 취득원가 += 受渡金額(USD)
現売: 취득원가 -= 취득원가 × (n / 수량), 수량 -= n
취득단가 = 취득원가 / 수량
```

- 수량이 0이 된 종목은 목록에서 뺀다.
- 수량이 음수가 되면 2년보다 전에 산 주식이 있다는 뜻이다. 그 종목은 평가에서 빼고 경고한다.
- 엔으로 결제한 체결(`受渡金額`이 엔)의 처리는 PRD 열린 질문 2에서 정한다. 구현 전에 정해야 한다.

## 금액·표시
- 통화는 시장이 정한다. 일본 = JPY, 미국 = USD. 두 통화를 섞지 않고 시장별로 합계를 내며, 환율은 쓰지 않는다.
- 계산은 `number` 원값으로 하고, 반올림은 표시할 때만 한다. 파싱에 `parseInt`를 쓰지 않는다.
- JPY: 금액은 정수에 쉼표. 단가는 CSV 값 그대로(소수가 있으면 그대로) 보인다.
- USD: 단가·금액 모두 소수 2자리
- 부호: 양수는 `+`, 음수는 `-`, 0은 부호 없음. 색은 쓰지 않는다.

## 시세
- `QuoteProvider`: 종목 코드 목록을 받아 코드별 현재가(또는 없음)를 돌려준다.
- yahoo: 일본은 `<코드>.T`, 미국은 티커 그대로 조회한다. 비공식 API라서 브라우저에서 직접 부르지 않고 Server Action에서만 부른다.
- 대시보드를 열 때와 CSV를 올린 직후에 받는다. 캐시는 두지 않는다.
- 시세를 못 받았을 때의 동작은 PRD 핵심 기능 3을 따른다.
- `TRIZON_QUOTES=fake`면 고정 현재가를 주는 fake provider를 쓴다(e2e용).

## 저장
- localStorage의 키 하나에 종류별(`ポートフォリオ`, `約定履歴`) 마지막 결과를 둔다. 가져온 시각, 보유 종목, 경고를 저장하고 CSV 원문은 저장하지 않는다.
- 저장 형식에 버전 번호를 넣는다. 읽지 못하거나 버전이 다르면 빈 상태로 시작하고 다시 올리라고 안내한다.
- localStorage 접근은 `lib/holdings/store.ts`에만 둔다. 로그인 단계에서 Supabase 유저별 저장으로 바꿀 때 이 모듈만 교체한다.

## 테스트
- `lib/`는 Next 없이 Vitest로 돈다. 테스트는 네트워크를 쓰지 않고, 시세는 fake provider가 준다.
- 가짜 CSV는 PRD 표의 값으로 만든다. Shift_JIS 판별은 인코딩한 바이트로 확인한다. 실제 CSV의 종목·수량·금액은 코드·테스트에 옮기지 않는다.
- e2e는 Playwright로, `TRIZON_QUOTES=fake` 상태에서 가짜 CSV 2개를 올려 확인한다.
- 실제 CSV는 `download/`에 두고 화면에서 직접 확인한다.

| PRD 완료 기준 | 확인하는 테스트 |
|---|---|
| 1. 랜딩, 대시보드 이동 | e2e |
| 2. 4종목, 수량·취득단가, 시장 구분 | `sbi/*` 단위 + e2e |
| 3. 평가액·평가손익, +/-, 소수 보존 | `evaluate`·`format` 단위 + e2e |
| 4. 시장별 합계 | `evaluate` 단위 + e2e |

## 1단계 구현 순서
1. 스캐폴드: `create-next-app`(TS, App Router, ESLint, `src/` 없음, Tailwind 없음). `.gitignore`는 지금 항목을 유지하고, Next 기본 항목과 `*.csv`를 더한다.
2. `lib/sbi/csv.ts` 이식 + 단위 테스트
3. `detect`·`portfolio`·`us-trades`: `tdd` 스킬로 테스트부터 쓴다.
4. `evaluate`·`format`
5. `quotes`(yahoo·fake)
6. `store`
7. 최소 화면(랜딩·대시보드)
8. e2e
9. 이 문서를 실제 구조로 고친다.

커밋은 기능별로 나누고(영어 Conventional Commits), 1단계 전체를 PR 하나로 올린다.
