# SBI CSV 형식·다운로드 동선·파싱 방식

현재 앱이 받는 SBI CSV는 아래 4종이다. 각 파일의 **받는 곳 → CSV 구조 → 파싱 규칙**을 정리했다. 메뉴는 앱의 [`guide.ts`](../lib/sbi/guide.ts)에 적힌 안내 기준이며, 아래 CSV는 실제 계좌 데이터가 아닌 형식 설명용 합성 예시다. 설명에 필요 없는 열은 생략했다.

## 다운로드 동선 한눈에 보기

| CSV | SBI에서 누르는 순서 | 다운로드 범위 |
|---|---|---|
| 실현손익 `実現損益` | **口座管理 → My資産 → 実現損益 → 実現損益詳細 → CSVダウンロード** | `約定日`: 처음부터 오늘까지 |
| 보유목록 `ポートフォリオ` | **ポートフォリオ → CSVダウンロード** | 현재 보유목록 전체. 페이지 일부만 받지 않도록 확인 |
| 미국주식 약정이력 `約定履歴` | **外国株式 → 取引照会 → 約定履歴 → 米国株式(現物) → CSVダウンロード** | 앱 안내 기준 최근 2년. 1,000건이 넘으면 기간을 나눠 여러 파일 |
| 배당·분배금 `配当・分配金` | **My資産 → 配当・分配金 → CSVダウンロード** | `受渡日`: 처음부터 오늘까지 |

실현손익과 배당은 같은 시작일·종료일로 받는다. 내려받은 파일은 앱 `/sbi`에서 드롭하거나 선택한다. 각 카드의 **SBI証券에서 받는 곳**, 이미 가져온 카드의 **받는 방법 · 뜻 다시 보기**에서도 이 동선을 볼 수 있다.

## 공통: CSV를 어떻게 읽는가

처리 순서는 `파일 바이트 → 텍스트 → 행·셀 배열 → 종류 판별 → 종류별 데이터`다.

1. **문자 인코딩:** UTF-8로 먼저 해석하고 실패하면 SBI 기본 형식인 Shift_JIS(CP932)로 읽는다. UTF-8 BOM도 지원한다.
2. **CSV 분리:** 텍스트를 문자 단위로 순회한다. 따옴표 안의 쉼표·줄바꿈은 셀 내용으로 두고, `""`는 따옴표 하나로 읽는다. CRLF 줄바꿈도 처리한다.
3. **셀 정리:** NFKC 정규화와 앞뒤 공백 제거. `銘柄（コード）` → `銘柄(コード)`, `ＮＴＴ` → `NTT`. 행 끝의 빈 셀은 제거하고 빈 줄은 표 경계로 남긴다.
4. **종류 판별:** 파일명 대신 `ポートフォリオ一覧`, `約定履歴`, `商品` 등의 행·머리글을 찾는다. 카드에 잘못 놓아도 내용에 맞는 파서로 보낸다.
5. **열 찾기:** 표의 시작은 특정 첫 열로 찾고, 나머지 열은 이름으로 찾는다. 정확히 같은 열 이름을 우선하며, 없으면 `実現損益(税引前・円)`처럼 괄호 설명이 붙은 열도 찾는다.
6. **값 변환:** 금액의 쉼표·공백·`円`을 제거해 숫자로 바꾼다. 빈칸·`-`는 `null`. `2026/9/24`는 `2026-09-24`로 맞춘다. `150.0000USD` 같은 통화 접미사는 미국주식 파서에서 별도로 읽는다.

구현: [`csv.ts`](../lib/sbi/csv.ts)의 `decodeCsvBytes`, `parseCsv`, `findColumn`과 [`parse.ts`](../lib/sbi/parse.ts)의 `detectKind`.

## 1. 실현손익 — 実現損益

**동선:** 口座管理 → My資産 → 実現損益 → 実現損益詳細 → CSVダウンロード

**형식:** 조회기간 등의 머리말 뒤에 **상품별 합계 표 하나**가 온다. 현재 지원하는 예는 `商品: すべて`로 받은 `ALLTYPE_*.csv` 형식이다. 파일명 자체는 판별 조건이 아니다.

```csv
"すべて"

"約定日","2024/1/1-2026/9/28"

"商品","実現損益(税引前・円)","利益金額(円)","損失金額(円)"
"国内株式(現物)","+12,000","20,000","-8,000"
"米国株式","-3,500","1,500","-5,000"
"合計","+8,500","21,500","-13,000"
```

**파싱:** `parseRealized()`.

- 첫 열이 `商品`이고 `実現損益` 열이 있는 행을 표 머리글로 찾는다.
- 그 앞의 `約定日` 행에서 조회기간을 읽고, 머리글 다음부터 빈 줄까지 상품별 행을 읽는다.
- 결과는 `period`, `beforeTax`, 상품별 `rows`, `total`로 나눈다. 세전 여부는 머리글의 `税引前`으로 판별한다.
- `合計`가 있으면 우선 사용하고, 없으면 상품별 금액을 더한다. 둘의 차이가 1엔을 넘으면 경고한다.

이 형식에는 종목별·거래별 상세가 없으므로 해당 상세를 복원하지 않는다.

## 2. 보유목록 — ポートフォリオ

**동선:** ポートフォリオ → CSVダウンロード

**형식:** 단일 표가 아니라 **표 제목 → 머리글 → 보유 행 → 구분별 합계**가 반복되고 마지막에 `総合計`가 온다. 현물·신용·투자신탁의 머리글이 서로 다르다.

```csv
"ポートフォリオ一覧",
"株式（現物/特定預り）",
"銘柄（コード）","数量","取得単価","現在値","損益","評価額",
"7203 トヨタ",100,2500,2800,+30000,280000,
"株式(現物/特定預り)合計",
"評価額","含み損益",
280000,+30000,
"株式（信用）",
"銘柄（コード）","売/買建","数量","建単価","現在値","損益","建代金",
"6758 ソニーＧ","買建",100,3000,3200,+19000,300000,
"投資信託（金額/NISA預り（つみたて投資枠））",
"ファンド名","数量","取得単価","現在値","損益","評価額",
"テスト全世界株式",200000,20000,25000,+100000,500000,
"総合計",
"評価額","建代金","含み損益",
780000,300000,+149000
```

**파싱:** `parsePortfolio()`와 `readStocks()`·`readMargins()`·`readFunds()`.

- 셀이 하나인 행을 표 제목으로 보관한다. 제목에서 `特定`·`一般`·`NISA成長`·`NISAつみたて` 등의 계좌구분을 읽는다.
- 아래 머리글 조합으로 표 종류를 구분하고, 다음 제목·빈 줄 전까지의 행을 읽는다.

| 표 종류 | 머리글 판별 | 추출하는 주요 값 |
|---|---|---|
| 현물 | 첫 열 `銘柄(コード)` + `取得単価` | 종목코드·이름·수량·취득단가·현재값·손익·평가액 |
| 신용 | 첫 열 `銘柄(コード)` + `建単価` | 종목코드·이름·매수/매도 구분·수량·건단가·현재값·손익·건대금 |
| 투자신탁 | 첫 열 `ファンド名` + `取得単価` | 펀드명·좌수·취득단가·기준가·손익·평가액 |

- `7203 トヨタ`는 앞의 4자리 코드와 뒤의 이름으로 나눈다. `285A` 같은 영문 포함 코드도 지원한다.
- 제목이 `…合計`이면 다음 행은 머리글, 그다음 행은 합계 값으로 읽는다. `総合計`는 별도 `csvTotal`에 둔다.
- 투자신탁은 `수량 × 기준가 ÷ 단위`를 CSV 평가액과 비교해 단위를 1 또는 10,000좌로 정한다. 비교할 값이 없으면 10,000좌로 둔다.
- 결과는 `stocks`, `margins`, `funds`, `csvTotal`, `holdingsComplete`로 나눈다. 행 합계 불일치, 모르는 표, `総件数` 대비 일부 행·페이지만 포함된 경우 경고한다.

CSV 내부에 기준 날짜가 없어 파일 수정시각을 별도로 받아 사용하며, 없으면 가져온 시각을 사용한다.

## 3. 미국주식 약정이력 — 約定履歴

**동선:** 外国株式 → 取引照会 → 約定履歴 → 米国株式(現物) → CSVダウンロード

**형식:** 조회기간 머리말 뒤에 **체결 한 건당 한 행**이 온다. 단가와 결제금액에는 `USD`가 붙는다.

```csv
"約定履歴"

"商品指定","約定開始年月日","約定終了年月日"
"すべて","2024年09月30日","2026年09月29日"

"国内約定日","銘柄","銘柄コード","市場","商品区分","取引","預り区分","約定数量","約定単価","国内受渡日","受渡金額/決済損益"
"2026/08/10","エヌビディア","NVDA","NASDAQ","米国株式","現買","特定",10,"100.0000USD","2026/08/12","1,000.00USD"
"2026/09/28","エヌビディア","NVDA","NASDAQ","米国株式","現売","特定",5,"150.0000USD","2026/09/30","749.00USD"
```

**파싱:** `parseUsTrades()`.

- 첫 열이 `国内約定日`이고 `銘柄コード`가 있는 행을 머리글로 찾는다.
- 필수 열은 `国内約定日`, `銘柄`, `銘柄コード`, `商品区分`, `取引`, `預り区分`, `約定数量`, `約定単価`다. 빠지면 파싱 오류를 낸다.
- `商品区分=米国株式`, `取引=現買/現売`, 양수 수량, USD 약정단가인 행을 거래 데이터로 만든다. 다른 상품이나 읽지 못한 행은 제외하고 경고한다.
- 일본어 날짜로 적힌 조회기간, 티커, 계좌구분, 결제일·USD 결제금액을 읽는다. 결과는 `period`, `trades`, 원본 행 수인 `sourceRowCount`다.
- `受渡金額/決済損益`은 **결제금액**으로 읽는다. 거래대금과의 차이는 수수료 추정값으로 따로 둔다. 이 열을 확정 실현손익으로 더하지 않는다.
- 1,000행 이상이면 다운로드 한도에 닿았다는 경고를 남긴다.

**여러 파일을 합칠 때:** 동일 원문의 SHA-256으로 같은 파일을 걸러내고, 체결은 거래 ID 또는 날짜·티커·매매구분·수량·단가·계좌구분·결제일·금액과 출현 순번으로 중복 제거한다. 한 파일 안에 값이 같은 실제 체결이 여러 건 있으면 보존한다. 이후 [`us-trades.ts`](../lib/sbi/us-trades.ts)에서 잔고를 추정한다.

## 4. 배당·분배금 — 配当・分配金

**동선:** My資産 → 配当・分配金 → CSVダウンロード

**형식:** 건수·조회기간 등의 머리말, **상품별 합계 표**, **건별 수령내역 표**가 한 파일에 들어 있다.

```csv
"検索件数","2"
"受渡日","2024/1/1-2026/9/28"

"商品","受取額(税引後・円)","受取額(税引後・USD)"
"国内株式(現物)","1,500",
"米国株式","2,345.6","15.5"
"合計","3,845.6",

"受渡日","口座","商品","銘柄名","数量","受取額(税引後・円)"
"2026/9/1","特定/一般","米国株式","アップル AAPL",10,"2,345.6"
"2026/6/30","NISA（成長投資枠）","国内株式(現物)","トヨタ自動車 7203",50,"1,500"
```

**파싱:** `parseDividends()`.

- `受渡日` 머리말에서 조회기간, `検索件数`에서 기대 건수를 읽는다.
- 첫 열이 `商品`이고 `受取額` 열이 있는 표에서 상품별 엔·USD 수령액과 `合計`를 읽는다.
- 첫 열이 `受渡日`이고 `銘柄名`이 있는 표에서 날짜·계좌·상품·종목명·수량·엔 수령액을 읽는다.
- 결과는 `period`, 상품별 `byProduct`, 건별 `items`, 엔 합계 `totalJpy`다. 합계는 **合計 행 → 상품별 엔 합 → 건별 엔 합** 순서로 선택한다. USD 열을 엔 금액에 중복해서 더하지 않는다.
- 건수가 맞지 않으면 경고한다. 건별 합과 합계의 차이는 절삭 오차를 고려해 `max(1엔, 건수 × 0.01엔)`까지 허용한다.

## 파싱한 문서는 어떻게 보관하는가

[`app/actions.ts`](../app/actions.ts)의 `importSbiCsv()`가 파싱 성공 여부를 확인한 뒤, 디코딩한 CSV 원문을 로컬 `data/sbi-imports.json`에 저장한다. `parseImports()`는 이 원문을 화면에서 읽을 때마다 다시 파싱한다.

실현손익·포트폴리오·배당은 종류별로 마지막 파일 하나만 보관한다. 미국주식 약정이력만 여러 파일을 보관해 병합한다. 실제 형식을 재현한 전체 합성 예시와 파서 테스트는 [`fixtures.ts`](../lib/sbi/fixtures.ts), [`parse.test.ts`](../lib/sbi/parse.test.ts), [`csv.test.ts`](../lib/sbi/csv.test.ts)에 있다.
