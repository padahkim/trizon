# SBI 미국주식 JPY 취득원가의 완전성 검증

2026-10-30 · [#56](https://github.com/padahkim/trizon/issues/56)

## 결론과 적용 범위

현재 남은 보유의 역사적 JPY 취득원가는 **알려진 0주에서 시작하는 전체 원장**에서 남아 있는 매수 원가가 모두 확정 JPY 결제일 때 계산할 수 있다. 부분 매도는 이동평균 비례로 원가를 줄인다. 매도 대금은 원가에서 빼지 않는다. USD 결제·결제 누락·양수 USD 기준 보유정보가 남아 있으면 전체 JPY 원가는 미상이며, 일부 JPY 근거만 있는 경우를 별도로 표시해야 한다. 보유가 실제 계산상 0이 된 뒤에는 이전 미상 근거를 버리고 신규 매수부터 다시 판단할 수 있다.

이 결론의 `complete`는 입력 원장과 계산 규칙에 대한 완전성이다. 업로드한 파일이 실제 전체 이력인지, SBI 화면과 원가가 같은지를 증명하지 않는다. 과거 매수가 빠져 있어도 매도 초과가 발생하지 않으면 누락을 감지할 수 없고, 원장에 없는 종목도 찾을 수 없다. 신뢰할 수 있는 시작점·원장 범위 확인이 별도로 필요하다.

검증 코드는 [독립 spike](../../spikes/sbi-jpy-cost.ts)와 [합성 테스트](../../spikes/sbi-jpy-cost.test.ts)에 있다. 현재 제품의 USD 보유 계산, 저장 형식, PRD, ADR을 변경하지 않는다. JPY 직접 입력, 환율 조회, 평가손익·세금 계산은 이 spike의 범위에 없다. 현재 환율로 환산한 금액은 역사적 JPY 원가가 될 수 없다.

## 확인한 현재 계약

기준: `e01575e`의 [#30 최종 구현](https://github.com/padahkim/trizon/issues/30)(PR #31 병합 포함).

| 경계 | 확인한 동작 |
|---|---|
| [거래 파서·원장](../../lib/sbi/us-trades.ts) | `米国株式`의 `現買`·`現売`만 사용한다. `settlement`는 금액과 `JPY`·`USD` 통화를 보존하며 없을 수도 있다. `円` 접미사는 JPY로 읽는다. |
| 거래 키·중복 제거 | 날짜·티커·매수/매도·계좌구분·수량·단가·수령일·결제금액/통화와 파일 안의 동일 거래 순번으로 키를 만든다. `mergeTrades`로 같은 키를 한 번만 남긴다. SBI 고유 체결 ID는 아니다. |
| 반영된 거래 방식 | [Dashboard](../../app/Dashboard.tsx)의 저장 시점에 해당 종목·계좌의 거래 키를 `includedTradeKeys`에 넣는다. 계산 시 그 키를 제외하고 미포함 거래를 반영한다. 빈 배열은 제외할 거래가 없다는 뜻이다. 같은 날 추가된 새 키도 반영한다. |
| 기존 날짜 방식 | `includedTradeKeys` 없이 `asOf`만 있는 저장값은 그 날짜 다음 날부터 반영한다. 기준일 당일 거래는 전부 제외한다. 다시 저장하기 전까지 이 호환 규칙을 유지한다. [ADR-0001](../adr/0001-us-holdings-baseline-cutoff.md), [ADR-0002](../adr/0002-us-holdings-reflected-trades.md). |
| 기준 보유정보의 통화 | 수량과 USD 취득단가만 있다. 양수 기준 수량 × USD 평단은 JPY 기준원가가 아니다. USD 평단이 0이어도 JPY 원가는 미상이다. |
| 0주 기준값 | 스키마가 USD 취득단가도 0으로 정규화한다. JPY 남은 원가도 확정 0이다. 기존 반영 거래를 제외한 새 매수부터 판단한다. 제품 보유표에서는 숨기지만 spike 결과에는 0주 행을 남겨 0과 미상을 비교한다. |
| 정렬·매도 | 종목·계좌구분별로 날짜순, 같은 날 매수 우선이다. 매도 초과는 계산 불가다. 부분 매도는 이동평균을 유지하며 수량이 0이면 원가를 초기화한다. |
| 현재 USD 원가 | USD 결제 매수는 결제금액, JPY 결제·결제 누락은 수량 × USD 체결단가를 쓴다. 이 대체 규칙을 JPY 원가에 적용할 수 없다. |

양수 기준 보유정보가 있으면 반영된 과거 원장의 JPY 매수액을 다시 더하지 않는다. 그 금액은 이미 매도된 분을 포함할 수 있고 기준값의 범위를 복원할 수 없다. 과거 JPY 결제가 모두 보여도 USD 기준 보유정보를 JPY 기준원가로 바꾸지 않는다. 기준값 삭제 후 전체 원장만으로 다시 계산하는 것은 별개의 입력이다.

거래키 방식에서 처음 올리는 과거 거래도 새 키로 처리된다는 기존 한계는 그대로다. 과거 CSV를 뒤늦게 추가하면 최신 CSV를 모두 확인한 뒤 현재 기준 보유정보를 다시 저장해야 한다. 동일 거래의 결제 정보가 바뀌어 키가 달라지는 경우도 자동 정정으로 간주할 수 없다.

## 실제 CSV 머리글 확인

사용자가 추가한 로컬 실제 CSV에서 **머리글만** 확인했다. 자산 행의 종목·수량·금액은 코드·테스트·문서에 옮기지 않았다. 확인한 미국주식 머리글은 다음과 같다.

```text
国内約定日,銘柄,銘柄コード,市場,商品区分,注文種別,取引,預り区分,約定数量,約定単価,国内受渡日,受渡金額/決済損益
```

현재 파서가 이름으로 찾는 필수 열과 선택 열 `国内受渡日`·`受渡金額/決済損益`이 있다. 추가 열 `市場`·`注文種別`은 계산에 사용하지 않는다. 같은 머리글 아래 전부 합성한 자산 행으로 파서 → spike 경계도 검증했다.

머리글만으로는 결제금액이 실제로 JPY인지, 부호·수수료 포함 범위가 무엇인지, 거래 이력이 완전한지 알 수 없다. 이 부분은 실제 검증 완료로 간주하지 않는다.

## 완전성 계약과 전파 규칙

`analyzeSbiJpyCost(trades, baselines)`는 기존 파서·스키마가 검증하고 `mergeTrades`로 중복 제거한 입력을 받는다. 기준 보유정보는 종목·계좌구분별 하나다. 외부 환율이나 현재 시세를 받지 않는다. 출력은 `positions`와 매도 초과 `issues`다.

| 원가 상태 | 출력 | 의미 |
|---|---|---|
| `complete` | `amount` | 남은 보유 전체의 JPY 원가를 알 수 있다. 확정 0도 포함한다. |
| `partial` | `knownAmount`, `reasons` | 남은 원가 중 확정 JPY 근거의 기여분만 안다. 이 금액은 전체 원가·전체 평단·전체 수익률의 분모가 아니다. |
| `unknown` | `reasons` | 남은 보유에 확정 JPY 근거가 없다. 금액을 0으로 대체하지 않는다. |
| 계산 불가 | `issues[].reason = "oversold"` | 보유보다 많이 팔았거나 매수 없이 팔았다. 해당 행은 `positions`에서 제외한다. 이후 매수로 순수량이 양수가 되어도 원가를 확정하지 않는다. |

미상 사유는 `usd-baseline`, `usd-settlement`, `missing-settlement`, `negative-jpy-settlement`다. 마지막 것은 부호 의미를 확인하지 않은 JPY 음수 결제를 임의로 절댓값 처리하지 않기 위한 보수적 분류다. 합성 계산의 확정 JPY 매수는 유한한 0 이상의 실제 취득 결제금액이라는 전제를 둔다. 실제 SBI 원가와의 일치는 후속 확인 대상이다.

1. 시작 수량이 0이면 JPY 원가는 확정 0이다. 양수 USD 기준 보유정보에서 시작하면 JPY 근거 없이 `unknown`이다. 반영된 원장 금액을 초기 원가에 보충하지 않는다.
2. 확정 JPY 매수는 그 결제금액을 아는 원가에 더한다. 금액이 `0JPY`여도 근거가 있다. 기존 잔량에 미상 근거가 없으면 `complete`, 있으면 `partial`이다.
3. USD 결제 또는 결제 누락 매수는 미상 근거를 추가한다. 기존 잔량에 JPY 근거가 있으면 `partial`, 없으면 `unknown`이다. USD 금액·USD 체결단가·현재 FX로 빈 원가를 채우지 않는다.
4. 매도 전 수량이 Q, 매도수량이 S라면 아는 원가 C를 `C × (Q − S) / Q`로 줄인다. 미상 원가도 같은 비율로 남기므로 양수 잔량에서는 완전성 상태와 미상 사유를 유지한다. JPY·USD·누락 중 어떤 매도 결제라도 원가의 새 근거가 되지 않는다.
5. 수량이 0이 되면 아는 원가·JPY 근거·미상 사유를 모두 초기화한다. 다음 JPY 매수만 있으면 `complete`, 다음 USD·결제 누락 매수만 있으면 `unknown`이다. 0주 상태 자체의 확정 0을 신규 보유의 JPY 근거로 세지 않는다.
6. 종목·계좌구분 사이에 완전성을 섞지 않는다. 전체 원가·손익 합계를 확정하려면 포함되는 모든 양수 행이 `complete`이고 계산 불가 행도 없어야 한다. `partial.knownAmount`를 더한 값은 일부 근거의 합일 뿐 전체 합계가 아니다. 집계·손익 구현은 후속 범위다.

수량 오차는 기존 계산의 `1e-9` 허용치를 사용한다. 0주에서의 양수 매도는 허용치 이내여도 계산 불가로 처리해 거짓 초기화를 막는다. 금액은 `number`로 유지하고 계산 중 엔 단위로 반올림하지 않는다. 분수 결과 테스트는 독립적인 고정 기대값과 작은 부동소수점 허용오차를 사용한다.

같은 날 매수 우선은 실제 체결 순서의 증명이 아니다. 특히 당일 전량 매도와 재매수가 섞이면 이 정렬에서 수량이 0을 지나지 않을 수 있다. CSV 행 순서만으로 초기화를 추측하지 않는다. 이 spike에서 원가 재확정은 **기존 정렬에서 확인된 0주** 또는 명시적 0주 기준 보유정보 이후에만 성립한다.

## 합성 예시와 고정 기대값

아래의 종목·수량·금액은 모두 가짜다. 날짜가 다른 거래는 나열한 순서로 처리한다.

| 입력 | 남은 수량 | JPY 결과 |
|---|---:|---|
| 2주 매수, 결제 30,300 JPY | 2 | `complete`: 30,300 |
| 2주 매수, 결제 200 USD / 결제 누락 | 2 | 각각 `unknown`: USD 결제 / 결제 누락 |
| 2주 30,000 JPY + 1주 USD + 1주 결제 누락 | 4 | `partial`: 아는 원가 30,000, 두 미상 사유 유지 |
| 2주 0 JPY + 1주 USD + 1주 결제 누락 | 4 | `partial`: 아는 원가 0. 미상 0이나 전체 확정 0이 아니다. |
| 2주 매수, 결제 0 JPY만 있음 | 2 | `complete`: 0 |
| 4주 10,000 JPY + 1주 15,000 JPY 매수 후 2주 매도, 매도대금 270,000 JPY | 3 | `complete`: 15,000. 평균 5,000 JPY 유지, 매도대금과 무관 |
| 4주 10,000 JPY + 1주 USD 매수 후 2주 매도 | 3 | `partial`: 아는 원가 6,000 |
| 양수 기준값 2주 × 100 USD, 반영된 과거 2주 30,000 JPY | 2 | `unknown`: 기준값의 JPY 원가 미상, 과거 30,000을 다시 더하지 않음 |
| 위 기준값 이후 같은 날 새 2주 60,000 JPY 매수 + 1주 매도, CSV 중복 반영 | 3 | `partial`: 아는 원가 45,000. 기준 수량과 새 키만 반영 |
| 0주 기준값, 반영된 과거 거래 제외, 같은 날 새 1주 15,000 JPY + 다음 날 2주 30,000 JPY | 3 | 거래키 방식 `complete`: 45,000 |
| 위 입력에서 기준값이 기존 날짜 방식 | 2 | 당일 새 거래도 제외, 다음 날분만 `complete`: 30,000 |
| JPY 미상 2주를 전량 매도 → 다음 날 1주 16,000 JPY 신규 매수 | 1 | `complete`: 16,000. 미상 이력 초기화 |
| USD 기준 4주 → 2주 매도 → 다음 날 2주 매도 → 이후 1주 32,000 JPY 매수 | 1 | 중간 2주는 `unknown`, 마지막 1주는 `complete`: 32,000 |
| USD 기준 2주, 같은 날 2주 매도 행과 1주 15,000 JPY 매수 행 | 1 | 매수 우선 계산상 `partial`: 아는 원가 5,000. 당일 초기화를 추측하지 않음 |
| 매수 없이 2주 매도 → 다음 날 4주 JPY 매수 | — | `oversold`. 양수 순수량만으로 복구하지 않음 |

그 밖에 종목·계좌구분 분리, 기준값만 있는 종목, 빈 거래키 목록, 분수 수량의 전량 매도, 혼합 원가 전량 매도 후 JPY/USD 재시작, 음수 JPY 결제를 검증한다. 테스트는 CSV 파서·스키마·중복 제거의 공개 경계만 사용하며 내부 상태를 검사하지 않는다.

## 남은 실제 대조 항목

실제 숫자 대조는 [#24](https://github.com/padahkim/trizon/issues/24)와 후속 사람 확인의 범위다. #24 완료는 이 spike의 착수 조건이 아니다. 머리글 확인과 합성 테스트 통과로 다음 항목을 완료한 것으로 보지 않는다.

- 실제 매수 `受渡金額/決済損益`의 JPY·USD 표기, 0·음수의 의미, 수수료·세금 등 포함 범위. 실제 행을 공개하지 않고 사용자가 SBI 화면과 대조한다.
- CSV의 2년·1,000건 제한을 넘어 현재 보유의 취득 이력이 모두 있는지, 잘린 페이지·누락 기간·나중에 추가한 과거 파일이 있는지. 초과 매도가 없다는 사실만으로 전체 이력을 보증하지 않는다.
- 부분 매도 후 엔화 잔존 원가와 SBI의 계산·반올림 방식, 같은 날 매수·매도 순서가 만드는 차이.
- 분할·병합·티커 변경·입출고 등 `現買`·`現売`만으로 복원할 수 없는 변화. 기존과 같이 자동 보정하지 않는다.
- 양수 USD 기준 보유정보를 다시 저장했을 때 JPY 근거가 사라지는 한계와 0주 재시작 이후의 원가를 실제 화면에서 구분할 수 있는지.

후속 제품 구현은 이 완전성 계약을 평가·집계 모델에 연결하고, 환율로 환산한 참고값과 역사적 JPY 원가를 구별해야 한다. 이 문서만으로 기존 정본이나 JPY 직접입력 기능을 바꾸는 결정을 하지 않는다.

## 재현

Node 22.18 이상·23 미만과 잠금 파일의 의존성을 사용한다. `next typegen`은 앱 전체 타입 검사에 필요한 `LayoutProps`를 생성한다.

```sh
npx next typegen
npx tsc --noEmit
npm test -- spikes/sbi-jpy-cost.test.ts
npm run lint
npm test
```

`npm test`는 spike를 포함한다. 실제 CSV·현재 환율·외부 시세·개인 저장소는 이 자동 검증의 입력이 아니다.
