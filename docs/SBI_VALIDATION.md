# 실제 SBI CSV 숫자 대조

[#24](https://github.com/padahkim/trizon/issues/24)의 확인 절차와 진행 상태다. 사용자가 실제 CSV를 앱에 직접 올리고 SBI 화면과 대조한다. 에이전트는 CSV 머리글만 확인한다. 가짜 CSV로 통과한 자동 테스트는 이 검증의 완료 근거가 아니다.

## 준비

1. 실제 CSV는 gitignore된 `download/`에만 둔다. 원문·종목·계좌번호·수량·금액은 코드, 테스트, 문서, 이슈, 커밋에 옮기지 않는다. 실제 보유가 보이는 스크린샷·브라우저 저장소·네트워크 응답도 공유하지 않는다.
2. [배포·리뷰 절차](DEPLOYMENT.md)를 따라 검증할 앱 주소와 커밋을 확인한다. 일반 시세를 쓰는 앱을 사용한다(`TRIZON_QUOTES=fake` 미설정). 주소별로 브라우저 저장소가 다르므로 검증 중 같은 주소를 쓴다.
3. SBI에서 최신 `ポートフォリオ`와 필요한 기간의 `約定履歴`을 받는다. 포트폴리오는 전체 범위를, 거래 내역은 최근 2년·파일당 1,000건 한도를 확인해 기간별 파일을 빠짐없이 준비한다. 다운로드 순서는 앱의 「CSV 올리기 안내」에 있다.
4. 기존 브라우저의 거래·기준 보유정보와 섞이지 않게 별도의 브라우저 프로필에서 시작한다. 기존 데이터를 지워 시작하면 2년보다 오래된 거래를 다시 받지 못할 수 있다.
5. 두 종류의 CSV와 기간별 거래 파일을 모두 올리고 파일별 반영 결과·잘린 페이지·건너뛴 거래·계산 불가 안내를 확인한다. 읽지 못하거나 잘린 파일은 먼저 해결한다.

## 머리글 확인

에이전트에게는 아래 표의 열 이름만 제공한다. 계좌명·추출 시각 같은 앞부분의 메타데이터와 보유·거래 행은 제공하지 않는다. 인코딩·열 순서·괄호 설명 처리는 [ARCHITECTURE 「CSV 읽기」](ARCHITECTURE.md#csv-읽기)를 따른다.

| 종류 | 현재 구현이 기대하는 머리글 |
| --- | --- |
| 일본주식 현물 | 첫 열 `銘柄(コード)`, 필수 `数量`·`取得単価`·`現在値` |
| 미국주식 거래 | 첫 열 `国内約定日`, 필수 `銘柄`·`銘柄コード`·`商品区分`·`取引`·`預り区分`·`約定数量`·`約定単価` |
| 미국주식 거래의 선택 열 | `受渡金額/決済損益`(취득원가), `国内受渡日`(거래 중복 식별에 사용) |

실제 SBI 원본의 머리글이 이 가정과 다르면 형식 수정 이슈를 연다. 차이가 난 열 이름과 가짜 값으로 만든 재현 예시만 적는다. `信用`의 `建単価`와 `投資信託`의 `ファンド名` 표는 지원 대상이 아니며, 건너뛰기 안내가 정상이다.

## 사람이 대조할 항목

모든 보유 종목을 계좌구분별로 대조한다. 같은 종목의 特定·NISA를 합쳐 비교하지 않는다. 앱은 일본주식을 엔, 미국주식을 달러로 표시하며 현금은 제외한다.

| 항목 | 확인 방법과 차이가 날 때 볼 것 |
| --- | --- |
| 일본주식 보유수량·취득단가 | 같은 시점의 SBI 보유 화면과 비교한다. CSV를 받은 뒤 매매했다면 새 파일로 다시 확인한다. |
| 미국주식 보유수량 | 기간별 거래 누락·2년 이전 매수·분할·병합·티커 변경을 먼저 확인한다. 계산 불가 경고가 없어도 과거 매수 누락으로 수량이 작게 나올 수 있다. |
| 미국주식 취득단가(U14) | 이동평균으로 계산한다. 달러 결제 매수는 수수료 포함 `受渡金額`을 원가에 쓰고, 엔 결제 또는 결제금액이 없는 매수는 수량 × `約定単価`를 쓴다. 엔 결제 매수가 있다면 수수료 미반영으로 설명되는 차이인지 사용자가 비공개로 계산해 확인한다. 단지 앱의 단가가 낮다는 이유만으로 수수료 차이라고 판정하지 않는다. |
| 종목별 평가액 | 현재가 × 보유수량이다. SBI와 앱의 시세 시각·통화·현재가를 맞춰 비교한다. `CSV 現在値`는 업로드한 CSV 가격이고, `시세 없음`은 취득가로 평가한 값이다. 시세가 다르거나 대체 평가 중이면 SBI 실시간 평가액과의 일치를 확인한 것으로 표시하지 않는다. |
| 시장별 합계 | 종목별 대조 뒤 엔·달러를 각각 비교한다. 미국주식의 엔 환산 평가액·환차손익은 1단계의 대조 대상이 아니다. |

먼저 CSV에서 추정한 결과의 차이를 확인한다. 이후 필요한 종목은 「보유정보 입력·관리」에서 SBI 현재 수량·달러 취득단가를 기준 보유정보로 입력한다. 과거 기간 CSV를 나중에 추가했다면 현재 보유정보를 다시 입력한다([ADR-0002](adr/0002-us-holdings-reflected-trades.md)). 직접 입력해서 일치한 결과는 CSV 추정값의 일치와 구분해 남긴다.

## 차이가 있을 때

원인별로 후속 GitHub 이슈를 열고 #24에 연결한다. 공개 기록에는 원인·재현 조건·기대 동작·실제 동작과 가짜 데이터만 쓴다.

- 머리글 차이: 실제 열 이름과 현재 기대 이름, 실패한 파일 종류를 적는다.
- 분할·병합·티커 변경: PRD 열린 질문 19에 따라 Yahoo 분할 이력을 이용한 자동 보정 이슈를 연다. 실제 보유 종목 대신 가짜 티커와 가짜 수량·단가로 재현한다.
- 설명되지 않는 수량·취득단가·평가액 차이: 거래 기간·계좌구분·시세 시각·수수료 적용 조건을 개인정보 없이 설명한다. 원인을 아직 모르면 미확인으로 남긴다.

## 확인 기록

2026-10-30 준비 확인: 로컬 `download/`에 있던 CSV에서 일본주식 현물 머리글이 위 가정과 일치함을 확인했다. 실제 SBI 원본인지와 숫자 일치는 확인하지 않았다. `約定履歴` 머리글은 확인할 파일이 없어 미확인이다. 보유·거래 값은 기록하지 않았다.

| #24 완료 조건 | 상태 |
| --- | --- |
| 실제 두 종류 CSV 업로드 후 일본·미국 종목별 보유수량·취득단가·평가액 대조 | 미확인 — 사용자 대조 필요 |
| 미국 취득단가 차이와 엔 결제 수수료의 관계 확인 | 미확인 — 사용자 대조 필요 |
| 분할·티커 변경 차이가 있으면 자동 보정 이슈 생성 | 미확인 — 차이 유무 확인 필요 |
| 실제 SBI 머리글 가정이 다르면 수정 이슈 생성 | 미확인 — 실제 원본 여부·미국 거래 머리글 확인 필요 |
| 확인 결과로 PRD 열린 질문 5를 닫거나 수정 | 진행 상태·검증 절차 연결, 질문은 유지 |

사용자는 수치 없이 다음 결과만 전달한다. 해당 사례가 없으면 `해당 없음`, 확인하지 못했으면 `미확인`으로 남긴다.

```text
검증한 앱 주소·커밋:
실제 SBI 원본 머리글: 일본 일치/차이/미확인, 미국 일치/차이/미확인
일본주식: 수량·취득단가·평가액 각각 일치/차이/미확인
미국주식: 수량·취득단가·평가액 각각 일치/차이/미확인
엔 결제 수수료로 취득단가 차이 설명: 예/아니오/해당 없음/미확인
분할·티커 변경 차이: 있음/없음/미확인
기준 보유정보 직접 입력: 있음/없음
후속 이슈 링크:
```

실제 대조가 끝나고 차이에 대한 설명 또는 원인별 후속 이슈가 갖춰지면 PRD 열린 질문 5와 #24를 갱신한다. 위 미확인을 자동 테스트 결과로 통과 처리하지 않는다.
